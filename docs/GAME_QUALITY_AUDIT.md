# DaiBed — аудит качества игры: ИИ, герои, бой, анимации, game feel

Дата: июнь 2026. Ветка: `claude/serene-pascal-n1tonn`.

Документ фиксирует: (1) найденные проблемы и **уже внесённые** исправления,
(2) целевую архитектуру героев, (3) приоритизированные списки дальнейших
улучшений (TOP-20 по каждому направлению).

Методика: матчи 4×4 ботов запускались headless через `--automatch`
(`xvfb-run ./DaiBed --automatch --runs 3 --speed 32 --minutes 16`),
сравнивались `automatch_stats.json` до/после каждого изменения.

## Часть 1. ИИ: что было сломано и что исправлено

### Базовая линия (до изменений)

Матч 4 команд **не завершался никогда**: за 8 минут — 2 ядра из 4,
дальше 5+ минут пустоты: боты Green 9 раз подряд падали в пустоту,
преследуя двух выживших, остальные «давили» базы без единицы урона.

| Проблема | Симптом в статистике | Причина (код) | Исправление |
|---|---|---|---|
| Бесконечное преследование | Chase = 70 % сэмплов лейтгейма, 0 убийств | `cleanupUrgency = (t-145)·5` рос без капа (~1700 очков к 480 с) и подавлял все интенты | Кап 140 очков + **бан бесплодной погони**: если 8 с дистанция не сокращается — Chase запрещён на 26 с, бот идёт сносить ядро (`BotMemory::chaseBanTimer`) |
| Дребезг ролей | 117–144 смены роли за матч (раз в 3.5 с) | Боты пинг-понгом заполняли дефициты ролей друг друга | Добровольная смена роли только при **избытке текущей роли** (`ownRoleSurplus`), минимальное время в роли 6–9 с |
| Давление без урона | Blue: 2843 сэмпла PressureCore, 0 урона ядру | Защитник чинил стену **мгновенно и бесконечно** (1 блок/кадр) | Кулдаун ремонта 0.75–1.3 с/блок: двое скоординированных атакующих перебивают одного защитника, одиночка — нет |

| Охота в одиночку | 4 бота по очереди подходили к дуэту и отступали | Радиус учёта союзников 9.5 блоков | При охоте на финальную цель радиус 16: подходящая стая считается силой |
| Sudden death не наступал | Таймаут при живых ядрах | Коллапс на 30-й минуте | Коллапс на **12-й минуте**; жертва Радона его не отменяет; после коллапса арена наносит 3 урона/2.5 с, базовое лечение и реген отключены |

| Одновременная смерть без победителя | `0 teams with lives`, матч висит | `CheckWinCondition` требовал ровно 1 команду | При полном вайпе побеждает команда с наибольшим суммарным HP |

### Архитектура принятия решений (как есть, работает хорошо)

Трёхуровневая: **стратегический план команды** (Economy / Pressure / Defense /
Cleanup, фазы по времени) → **роль** (Defender / Rusher / Collector / Fighter)
→ **интент** (10 utility-score-вариантов через `ConsiderBotDecision`).
Координация — через `TeamCoordinationBus` (сигналы AttackingCore /
DefendingCore / CallingForHelp), тюнинг — через JSON-геном (`BotTuningGenome`)
с генетическим алгоритмом. Эту структуру менять не нужно — все исправления
встроены в неё.

## Часть 2. Поведение «как в BedWars» — состояние

- **Роли**: есть и динамически меняются (теперь — стабильно, без дребезга).
- **Оценка риска**: `AssessFight` считает силу обеих сторон, союзников/врагов
  в радиусе, роль, цель на финальной жизни; теперь учитывает численный перевес
  и прекращает бесплодное преследование.
- **Защита базы**: `InspectCoreDefense` (17 позиций, ранги материалов
  Obsidian > Stone > Glass > Wood > Wool), ремонт + апгрейд слабых блоков,
  теперь с темпом установки.
- **Наступление**: выбор самой слабой/доступной базы (`SelectBestAttackTarget`:
  дистанция − повреждённость + защитники + занятость цели союзниками),
  A*-навигация с картой угроз, мосты с страховочными блоками.
- **Конец матча**: HuntPlayers, стая при охоте, sudden death гарантирует финал.

Оставшиеся слабости — в TOP-20 ниже (приоритетно: повторяющиеся падения
в пустоту у отдельных ботов, координированные «волны» штурма).

## Часть 3. Герои: текущее состояние и целевая архитектура

### Сейчас

6 героев (Радон, Орбита, Бром, Конвой, Лихо, Свидетель). Данные — в
`HeroSystem.cpp` (статические `HeroDefinition`). Активация — `UseHeroAbility`
с диспетчеризацией по `HeroId` в **одном** месте; Радон/Орбита/Бром/Конвой
реализованы полностью, Лихо/Свидетель — каркас (кулдаун + эффект + сообщение).
Боты теперь играют всеми шестью (см. Часть 4).

Проблемные места текущей реализации:
- `HeroRuntimeState` содержит поля конкретных героев (`radonProtected`,
  `orbitaMomentumStrike`, …) — при 10+ героях разрастётся;
- `Renderer.cpp` ветвится по `HeroId` для поз/свечений;
- `UseRadonAbility` читает клавиатуру (`IsKeyDown(ALT)`) внутри логики
  способности — ввод должен приходить параметром;
- эффекты Лихо/Свидетеля не реализованы.

### Целевая архитектура (расширяемая, без `if hero == X` по проекту)

```
HeroSystem (реестр)
 ├─ HeroDefinition (данные: имя, роль, описания, кулдауны)   ← уже есть
 └─ IHeroKit (поведение, 1 класс на героя, регистрируется фабрикой)
      ├─ OnAbility(AbilityContext&, slot)      // касты
      ├─ OnPassiveTick(HeroTickContext&, dt)   // пассивки
      ├─ OnCombatEvent(const CombatEvent&)     // заряд ульты, он-хиты
      ├─ BuildVisuals(std::vector<HeroDeviceVisual>&) // девайсы/ауры
      └─ BotPlan(BotAbilityQuery&) → желаемый каст     // мозг бота

struct AbilityContext {            // вместо доступа к Game напрямую
    Player& caster;
    World& world;
    EffectEmitter& effects;        // AddWorldEffect/FloatingText/Message
    CombatApi& combat;             // урон, knockback, проджектайлы
    DeviceRegistry& devices;       // турели/капканы/боты — общий контейнер
    AbilityInputs inputs;          // aim, altModifier — НИКАКОГО IsKeyDown
};
```

- `Game::UseHeroAbility(player, slot)` сводится к
  `HeroSystem::KitFor(player.GetHeroId()).OnAbility(ctx, slot)` —
  единственная точка диспетчеризации в проекте.
- Hero-специфичные поля уходят из `HeroRuntimeState` в
  `std::unique_ptr<IHeroState>` внутри кита (или `std::variant`).
- Девайсы (`BromVacuumBot`, `KonvoyTrap`, …) обобщаются в `HeroDevice`
  с типом-тегом — рендер и апдейт через общий список, как уже сделано
  для `HeroDeviceVisual`.
- Новый герой = 1 файл `HeroX.cpp` (данные + кит + регистрация в реестре)
  + текстуры. Ноль правок в Game/Renderer/BotAI.

Миграцию можно делать инкрементально: сначала перенести Лихо и Свидетеля
(они ещё каркасные), затем Брома/Конвоя (девайсы), последними Радона/Орбиту.

## Часть 4. Способности ботов (реализовано)

`Game::BotUseHeroAbility` (GameBotAI.cpp) — вызывается перед утилитами,
с кадансом решений 1.1/1.8/3.2 с (Hard/Normal/Easy). Касты идут через
`BotCastHeroAbility`, который глушит HUD-сообщения и звуки локального
игрока (`suppressLocalFeedback_`, `AudioSystem::SetMuted`).

| Герой | Способность 1 | Способность 2 | Ультимейт | Когда НЕ использовать |
|---|---|---|---|---|
| **Радон** | Толчок: враг < 4 бл. и (защита базы / у врага больше HP / враг у обрыва) | Молотов: враг 4.5–12 бл. в бою или при осаде | Прайм жертвы: ядро < 1/3 HP, критическая защита или враг у ядра; при мёртвом ядре — взрыв при враге < 4.5 бл. | Не перепрайм (toggle), не пушить дальше 4 бл. |
| **Орбита** | Дэш-сближение: цель 4.5–11 бл. при погоне/выгодном бое; дэш-отрыв при отступлении | Фантомный мост: осада + < 4 блоков + пустота впереди | Телепорт-побег: HP 18–40, враг < 6 бл., в сторону базы | Дэш в воздухе (лок), телепорт при HP < 18 (стоит здоровья) |
| **Бром** | Пылесос: железо ≥ 60, у базы, без врагов | Турель: золото ≥ 12 (+8 запас вне обороны), при защите или враге < 9 бл. | Сборка обороны: у базы при атаке/критической защите | Не тратить железо при < 60, не ставить турель в чистом поле |
| **Конвой** | Капкан: Defender у базы, в тишине | Наручники: враг < 5.5 бл. в бою | Купол: враг < 5 бл. при добивании/обороне/перевесе HP | Не тратить купол на полного HP врага в чистом поле |
| **Лихо** | Тихие шаги: цель < 14 бл. при осаде/охоте | Кровотечение: в клинче (< 3.5 бл.) | Маскировка: осада, до вражеского ядра < 30 бл. | Вне осады/охоты — копить |
| **Свидетель** | Эхо: бой < 8 бл. | Фазовый участок: бот застрял (> 1.4 с) | Контуры Войда: охота или t > 150 с | Слепые касты без целей |

Комбинации, которые возникают сами: Орбита «дэш → momentum strike»;
Конвой «наручники → купол» (тетер не даёт выйти из радиуса);
Радон «толчок к обрыву → Void hit»; Бром «ульта + турель» при обороне.

## Часть 5. Анимации (реализовано в этой ветке)

Персонаж был «кубом с шаром». Теперь (`Renderer.cpp`, процедурно, без ассетов):

- **Походка**: торс + 2 ноги + 2 руки; ноги шагают по синусоиде с амплитудой
  от скорости, руки в противофазе; частота выше при спринте; вертикальный
  боб торса; фаза смещена по id игрока (нет синхронного марша).
- **Прыжок/падение**: вертикальный стретч тела от |vy|, ноги поджаты в воздухе.
- **Приседание**: торс ниже и короче.
- **Удар**: рука с оружием выбрасывается вперёд-вверх, предмет делает
  выпад с наклоном вниз по `attackCooldown` (окно 0.26 с) — замах читается
  у всех: и у ботов, и у игрока.
- **Получение урона**: флеш тела/головы красным по `invulnerabilityTimer`.
- **Камера**: hit stop (сим-тик ×0.15 на 85 мс при убийстве, 45 мс при
  крит/комбо/W-tap), FOV-кик +5° при убийстве, +2.2° при тяжёлом ударе,
  поверх существующего спринт-FOV и шейков.

Каждая способность героя уже имеет фазы WindUp → Cast → Recovery
(`HeroAnimationState`) — новые герои должны заполнять их же.

## Часть 6. Game feel — что ощущалось дёшево и что сделано/предложено

| Ощущалось дёшево | Сделано | Дальше (предложение) |

| Игроки скользят без ног | Полный процедурный walk cycle | Наклон корпуса в сторону движения (требует rlPushMatrix-поворотов) |

| Стрельба молотовым у ботов без замаха | Анимации Cast у способностей | Телеграф зоны падения (декаль на земле 0.4 с) |
