# DaiBed 0.2.0 — Release Plan (networked alpha)

> Статус: черновик для обсуждения.
> Производное от `docs/ROADMAP.md` (Фаза 2), `docs/VISION.md` и
> `docs/NETWORK_PREP_PLAN.md`. Продолжение release-contract `RELEASE_0.1.0.md`
> (§4 «Что не входит в 0.1.0» → это и есть scope 0.2.0). После согласования файл
> становится рабочим контрактом: новые задачи не добавляются без явного решения
> и удаления задачи сопоставимого размера.

## 1. Формат релиза

**DaiBed 0.2.0** — публичная **сетевая** alpha: 2–8 человек играют полноценный
матч по сети **без разработчика рядом**.

Хост и игроки должны без помощи разработчика:

1. Поднять сервер/комнату из GUI (host) или подключиться по адресу (join).
2. Выбрать команду и героя в лобби, нажать «готов», стартовать матч.
3. Сыграть тот же цикл, что в 0.1.0 (ресурсы, магазин, стройка, бой, Кор), но
   **против и вместе с живыми людьми**, с ботами на свободных слотах.
4. Увидеть честный результат матча, переподключиться при обрыве.

0.2.0 демонстрирует, что главная формула (геройский BedWars) работает **по
сети при ~80 мс пинга**, а не только в локальном матче. Это alpha, а не
соревновательный релиз.

## 2. Целевая аудитория

- Тестировщики из 0.1.0, готовые играть друг с другом по сети (LAN / прямой IP).
- Игроки BedWars/Minecraft PvP, которым важен сетевой PvP с друзьями.
- Не позиционируется как ranked/matchmaking-продукт.

## 3. Что входит в 0.2.0

### 3.1 Сетевой матч

- Authoritative headless-сервер + клиенты по UDP (готово, см. §"Текущий статус").
- Удалённый человек может **всё то же, что локальный игрок/бот**: движение,
  бой ближний и дальний, стройка/ломание, способности, **покупки в магазине**,
  сундуки/инвентарь.
- Client-side prediction своего игрока + интерполяция чужих (готово).
- Боты занимают свободные слоты; матч заполняется до размера команд.

### 3.2 Лобби и подключение

- Host/Join из GUI без правки CLI: имя сервера, порт, пароль, режим/размер
  команд/боты/карта — задаются хостом и являются **единственным источником**
  правил матча.
- Выбор команды/героя/готовности в лобби; старт по готовности.
- Reconnect: при обрыве слот сохраняется, при возврате игрок получает полный
  baseline мира и приватное состояние.

### 3.3 Поток матча по сети

- Смерть показывает убийцу/причину/время до респауна — реплицируется на клиент.
- Final death визуально отличается; spectator-камера после выбывания.
- collapse / sudden death работают как правило матча (не только в automatch).
- Экран победы/результата на клиенте; из него — новая игра или выход.

### 3.4 Режимы, карта, герои

- Рекомендуемый режим: 4 команды × до 4 игроков (микс людей и ботов).
- Одна отполированная Классическая арена (как в 0.1.0).
- Те же шесть готовых героев, корректно работающие по сети (касты, устройства,
  статусы, зоны видны и применяются у всех клиентов).

### 3.5 Стабильность сети

- Команды/способности/покупки не теряются при разумной потере пакетов
  (reliability/ack).
- Нет рывков чужих игроков и динамики (render-interpolation между тиками).
- Матч 4 живых игроков стабилен при 80 мс пинга (критерий `ROADMAP` Фазы 2).

## 4. Что НЕ входит в 0.2.0 (это 0.3+)

- Party/друзья, быстрый инвайт.
- Ranked, MMR, сезоны.
- Косметика и мета-прогрессия.
- Лавовая/Космическая карты релизного качества.
- Полная миграция на `MatchSimulation` (6B) и полная архитектура `IHeroKit`.
- Реплеи, killcam, расширенная послематчевая аналитика.
- Шифрованный/challenge-хендшейк (0.2.0 — пароль/токен на connect, LAN-доверие).
- Matchmaking/публичный server browser (только прямой IP / LAN).

## 5. Текущий статус сети (база, на которой строится 0.2.0)

Фундамент 0.1A–0.1U уже в дереве и проверен smokes (Release, 2026-06-27):

- ✅ Wire-протокол v8, реальный UDP transport, closed multiplayer
  (`--mp-loopback-smoke` → `MP_LOOPBACK_SMOKE_OK`).
- ✅ GUI-клиент, prediction/reconciliation/interpolation, visibility-фильтр.
- ✅ **Phase A — покупка в магазине по сети** (`--network-purchase-smoke` →
  `PURCHASE_SMOKE_OK`: buy/dedupe/deniedFunds/deniedRange).
- ✅ **Phase B — ranged + aim из команды** (`--network-ranged-smoke` →
  `NETWORK_RANGED_SMOKE_OK`: fireball/bow/blaster spawn + aim=ok).
- ✅ **Phase C — клиент применяет динамику снапшота** (`--client-dynamic-apply-smoke`
  → `CLIENT_DYNAMIC_APPLY_SMOKE_OK`: projectiles/explosives/hazardZones/heroDevices/
  statusEffects материализуются).
- ✅ Сетевые melee/place/break (`--network-actions-smoke` →
  `NETWORK_ACTIONS_SMOKE_OK`: melee=ok place=ok break=ok). *(Ранее smoke был
  красным на melee — оказалось артефактом теста: он переиспользовал локального
  игрока как сетевого, из-за чего held-item читался из глобального UI-слота, и
  бил врага сквозь спавн-защиту на тике 0. Реальный сетевой melee не был сломан;
  smoke приведён к реальным условиям.)*
- ✅ **Репликация анимаций** — `animationState`(+timer/duration) в `PlayerSnapshot`;
  клиент адаптирует серверную позу (walk/run/jump/attack/cast/death) вместо
  заморозки на Idle (`--client-dynamic-apply-smoke`: animation=ok). Протокол v9.
  Свой (предсказанный) игрок выводит локомоцию **локально** из предсказанной
  скорости (нулевой лаг), событийные позы (атака/каст/смерть) — с сервера
  (`Player::AdvanceAnimation`; smoke `ownLocal=ok`).
- ✅ Базовое лобби + connect с паролем (`--loopback-two-client-smoke`, two-process).

## 7. Release gates

### Gate A — Сборка и упаковка

- [ ] Release x64 собирается без новых предупреждений (`DAIBED_ENABLE_NETWORK=ON`).
- [ ] Сетевой билд запускается на чистой машине; версия `0.2.0` видна в игре.
- [ ] Host и Join доступны из меню без правки CLI/конфигов.

### Gate B — Полный сетевой путь

- [ ] Хост поднимает матч, ≥2 клиента подключаются и видят один мир.
- [ ] Каждый удалённый игрок может двигаться, бить ближний/дальний бой, строить/
      ломать, кастовать, **покупать**, пользоваться сундуком — наравне с ботом.
- [ ] Смерть/респаун/final death/spectator работают на клиенте.
- [ ] Reconnect восстанавливает изменённый мир и приватный инвентарь.
- [ ] Экран результата + новая игра/выход; нет softlock.

### Gate C — Стабильность сети

- [ ] Все network-smokes зелёные: purchase, ranged, dynamic-apply, **actions
      (включая melee)**, mp-loopback, loopback-two-client, client-input,
      reconnect-baseline (новый), lobby-parity (новый).
- [ ] Soak: матч 4 живых игроков при искусственных 80 мс RTT + умеренной потере
      пакетов проходит до конца без рассинхрона/краша.
- [ ] Два-процессный прогон host+клиенты на одной машине стабилен N минут.
- [ ] Регрессия single-player: seed-фиксированный automatch детерминирован
      (сетевой путь зовётся только в `NetworkServerTick` — automatch инертен).

### Gate D — Паритет и баланс по сети

- [ ] Удалённый человек не слабее бота (может то же множество действий).
- [ ] Касты/устройства/зоны/статусы героев видны и применяются у всех клиентов.
- [ ] Боты на свободных слотах ведут себя как в 0.1.0 (та же активность/winrate).

### Gate E — Презентация (клиент)

- [ ] Нет временных debug-строк у клиента (overlay только по dev-флагу).
- [ ] Лобби/HUD/оверлеи читаются; нет битой кодировки/обрезанного текста.
- [ ] Сетевые состояния (connect/denied/disconnect/reconnect/pause) имеют
      понятную обратную связь.

## 8. QA matrix

### 8.1 Ручная (минимум)

| Область | Сценарии |
|---|---|
| Лобби | host create, join по IP, неверный пароль, выбор team/hero, ready, start |
| Сетевой бой | ближний/дальний у клиента, KB, void-kill, final-kill, kill-feed |
| Экономика | покупка клиентом, недостаток ресурсов, массовая покупка, сундук |
| Стройка | place/break/мост у клиента, чужая защита, синхронность блоков |
| Жизненный цикл | смерть с живым Кором, без Кора, spectator, победа/результат |
| Сеть | reconnect после стройки, обрыв хоста, лаг 80мс, потеря пакетов |
| Боты | свободные слоты, активность первой минуты, нет преимущества слота |

### 8.2 Automatch / regression

- Single-player automatch не регрессирует (детерминизм на фикс-seed).
- Network smoke suite зелёная в CI/локально перед RC.
- Soak: длинный сетевой матч (4 человека-эквивалента) без роста памяти/краша.

### 8.3 Производительность сети

- Стабильный FPS у клиента при полном матче и массовой стройке.
- Трафик: delta-снапшоты меньше full; bandwidth в разумных рамках на 8 игроков.
- Нет рывков чужих игроков/динамики (интерполяция).

## 9. Definition of Done задачи

1. Реализован пользовательский сетевой сценарий, не только внутренняя логика.
2. Есть ручной способ проверить + по возможности headless smoke.
3. Release build (`DAIBED_ENABLE_NETWORK=ON` и `OFF`) собирается без новых
   предупреждений.
4. Single-player automatch не показывает регрессию (если затронута симуляция).
5. Обновлены `NETWORK_PREP_PLAN.md` / known issues.
6. Не нарушает принципы `VISION.md`.

## 10. Release process

### Alpha freeze
- Зафиксировать scope этого файла; закрыть P0; запустить полную QA-матрицу.

### Release candidate
- Версия `0.2.0-rc.1`; чистый Release package с сетью; manual + smoke + soak;
  зафиксировать known issues.

### Release
- Версия `0.2.0`; git tag `v0.2.0`; changelog + инструкция host/join +
  системные требования; сохранить regression seeds и сетевые soak-результаты.

## 11. Метрики успеха 0.2.0

- Двое тестировщиков самостоятельно поднимают и играют матч по сети < 5 минут.
- Удалённый игрок субъективно «не калека»: бой/экономика/стройка ощущаются как
  локально, лаг терпим при ~80 мс.
- Reconnect возвращает в тот же матч с целым миром.
- Нет критических краша/softlock/рассинхрона за тестовую сессию.
- Есть желание сыграть ещё матч с друзьями.
