# DaiBed 0.1.0 - Release Plan

> Статус: черновик для обсуждения.
> Цель документа: зафиксировать состав версии 0.1.0, критерии готовности и
> порядок работ. После согласования этот файл становится рабочим release
> contract: новые задачи не добавляются в 0.1.0 без явного решения.

## 1. Формат релиза

**DaiBed 0.1.0** - публичная single-player alpha с полноценным матчем против
ботов.

Игрок должен без помощи разработчика:

1. Запустить игру.
2. Понять цель матча и выбрать героя.
3. Собрать ресурсы, купить предметы, строить и сражаться.
4. Уничтожить EnergyCore противника или проиграть свой.
5. Увидеть понятный результат матча и начать новый.

Версия демонстрирует главную формулу проекта: **геройская надстройка над
BedWars**, а не полный набор возможностей будущего сетевого релиза.

## 2. Целевая аудитория

- Игроки BedWars и Minecraft PvP.
- Игроки, которым интересны герои, способности и командные роли.
- Ранние тестировщики, готовые оценивать механику и game feel.

0.1.0 не должна позиционироваться как законченная соревновательная игра.

## 3. Что входит в 0.1.0

### 3.1 Игровой цикл

- Один полностью играбельный матч против ботов.
- Ресурсы, генераторы и магазин.
- Строительство и разрушение блоков.
- EnergyCore, респаун и final life.
- Воид как полноценная часть тактики.
- Экран победы/поражения и повторный запуск матча.

### 3.2 Режимы

- Основной рекомендуемый режим: четыре команды по четыре игрока.
- Остальные уже существующие локальные режимы могут остаться, если они не
  требуют отдельного баланса и не создают критических ошибок.
- Бот-режим является частью продукта, а не технической демонстрацией.

### 3.3 Карта

- Одна отполированная Классическая арена.
- Базы визуально различимы и легко читаются.
- Понятные пути к соседним островам и центру.
- Центральная зона создаёт конфликт за ресурсы.
- Строительство игрока существенно меняет карту по ходу матча.

Лавовая, Космическая и другие карты не блокируют 0.1.0.

### 3.4 Герои

- В меню доступны только герои с законченными игровыми эффектами.
- У каждого доступного героя есть понятная ниша, пассивка, две активные
  способности и ультимейт.
- Касты имеют читаемую обратную связь и не требуют знания внутреннего кода.
- Боты корректно используют доступных героев.

- Завершить Лихо и Свидетеля к 0.1.0.

### 3.5 Боты

- В первую минуту минимум половина команды покидает радиус 12 блоков от
  своего кора.
- У домашнего генератора не простаивает вся команда.
- Боты собирают ресурсы, закупаются, строят мосты, защищают и атакуют.
- Боты не повторяют один заведомо смертельный маршрут много раз подряд.
- Матчи завершаются победителем, а не систематическим timeout.
- Ошибки ботов выглядят человеческими и дают игроку понятные возможности.

### 3.6 Управление и game feel

- Ходьба, спринт, шифт, прыжок, досягаемость, knockback и постановка блоков
  проходят отдельный Minecraft-feel аудит.
- Очевидные расхождения с мышечной памятью Minecraft исправлены либо явно
  обоснованы в `docs/FEEL_AUDIT.md`.
- Попадание, промах, урон, смерть, покупка и установка блока различимы по
  звуку и визуальной реакции.
- Камера не вызывает дискомфорт при стандартных настройках.

### 3.7 UX матча

- Первая минута объясняет кор, ресурсы, магазин, строительство и героя.
- Смерть показывает убийцу, причину смерти и время до респауна.
- Final death визуально отличается от обычной смерти.
- Игрок понимает, какой кор уничтожен и какая команда выбыла.
- Экран конца матча показывает победителя и основные результаты.
- Из конца матча можно начать новую игру или выйти в меню.

### 3.8 Настройки

- Разрешение, полноэкранный режим и лимит FPS.
есть 3 режима
оконный,
безрамочный
и полноэкранный
- Громкость или минимум общий mute.
- Чувствительность мыши и переназначение основных клавиш.
- FOV.
- Переключатели подсказок и миникарты.
- Настройки сохраняются между запусками.
- Желательно: снижение camera shake и вспышек для доступности.

### 3.9 Упаковка

- Windows Release x64 build запускается на чистой пользовательской машине.
- Версия `0.1.0` видна в игре.
- В архив входят только необходимые бинарники и ассеты.
- Присутствуют README, управление, системные требования и известные проблемы.
- CrashLogger сохраняет пригодный для диагностики отчёт.
- Указаны лицензии сторонних компонентов, включая raylib.

## 4. Что не входит в 0.1.0

- Настоящий сетевой мультиплеер.
- Authoritative server, prediction и reconciliation.
- Лобби, reconnect, party и друзья.
- Ranked, MMR и сезоны.
- Магазин косметики и мета-прогрессия.
- Три карты релизного качества.
- Полная миграция на `MatchSimulation`.
- Полная архитектура `IHeroKit`.
- Реплеи, killcam и расширенная послематчевая аналитика.

Эти задачи остаются важными, но относятся к 0.2+ и долгосрочному roadmap.

## 5. Release gates

Версия не считается готовой, пока не выполнены все обязательные gates.

### Gate A - Сборка и запуск

- [x] Release x64 собирается без новых предупреждений и открытия консоли.
- [x] Игра запускается без установленной среды разработки.
- [x] Первый запуск не требует ручного создания конфигов.
- [x] Повторный запуск сохраняет настройки.
- [x] Выход из игры завершается без зависших процессов.

### Gate B - Полный пользовательский путь

- [ ] Новый игрок может начать матч без внешней инструкции.
- [ ] Можно пройти весь цикл от меню до победы/поражения.
- [ ] Работают смерть, респаун и final death.
- [ ] Работает рестарт матча.
- [ ] Нет блокирующих softlock-состояний.

### Gate C - Стабильность

- [ ] Не менее 20 ручных матчей без crash.
- [x] Не менее 100 headless automatch-прогонов без crash/hang.
- [x] Нет систематических timeout в стандартном automatch.
- [x] Два запуска с одинаковым seed воспроизводят одинаковый результат.
- [x] CrashLogger проверен искусственно вызванным сбоем или тестовым сценарием.

### Gate D - Боты и баланс

- [x] Все команды проявляют активность в первые 60 секунд.
- [x] Нет команды с устойчивым преимуществом стартового слота.
- [x] Нет героя с очевидно сломанным automatch winrate.
- [x] Боты используют магазин, блоки и способности.
- [x] Повторные падения по одному маршруту находятся в допустимом диапазоне.

### Gate E - Презентация

- [ ] В меню и HUD нет временных debug-строк.
- [ ] Нет битой кодировки или обрезанного текста.
- [ ] Основные состояния имеют звук и визуальную обратную связь.
- [ ] UI читается в поддерживаемых разрешениях.
- [ ] Название игры и версия отображаются последовательно.

## 7. QA matrix

### 7.1 Ручная проверка

Проверить минимум:

| Область | Сценарии |
|---|---|
| Меню | первый запуск, повторный запуск, смена настроек, выход |
| Герои | каждый доступный герой, все способности, смерть во время каста |
| Магазин | своя база, чужая база, недостаточно ресурсов, массовая покупка |
| Строительство | край блока, шифт, быстрый мост, высота, чужая защита |
| Бой | обычный удар, combo, knockback, void kill, final kill |
| Жизненный цикл | смерть с живым кором, смерть без кора, spectator, победа |
| Карта | каждая база, центр, генераторы, отсутствие застреваний |
| Настройки | поддерживаемые разрешения, fullscreen, mute, bindings |

### 7.2 Automatch matrix

Перед release candidate:

- 100+ матчей на Классической арене.
- Минимум 10 фиксированных regression seeds.
- Все доступные герои представлены примерно равномерно.
- Проверка каждого стартового team slot.
- Проверка Easy, Normal и Hard, если сложности доступны игроку.
- Отдельный длительный soak run.

Сохранять по каждому набору:

- winrate команд и героев;
- медиану и p95 длительности;
- timeout/crash/hang rate;
- число уничтоженных коров;
- final deaths и void falls;
- stuck samples и повторные маршруты падения;
- распределение ролей и интентов.

### 7.3 Производительность

- Стабильный frame rate на целевой минимальной машине.
- Отсутствие заметных фризов при массовом строительстве и бое.
- Ограниченный рост памяти в длинном матче.
- Headless automatch не деградирует по скорости после нескольких поколений.

## 8. Definition of Done задачи

Каждая задача для 0.1.0 считается завершённой, если:

1. Реализован пользовательский сценарий, а не только внутренняя логика.
2. Есть ручной способ проверить результат.
3. Release build собирается без новых предупреждений.
4. Automatch не показывает регрессию, если задача затрагивает симуляцию.
5. Обновлена связанная документация или known issues.
6. Изменение не нарушает принципы `VISION.md`.

## 9. Release process

### Alpha freeze

- Зафиксировать scope этого документа.
- Не добавлять новые механики без удаления задачи сопоставимого размера.
- Закрыть P0 и начать полную QA-матрицу.

### Release candidate

- Повысить версию до `0.1.0-rc.1`.
- Собрать чистый Release package.
- Выполнить manual smoke и automatch matrix.
- Зафиксировать known issues.
- Не менять баланс без повторного полного automatch-прогона.

### Release

- Повысить версию до `0.1.0`.
- Создать git tag `v0.1.0`.
- Архивировать символы сборки отдельно от пользовательского пакета.
- Опубликовать changelog, управление и форму обратной связи.
- Сохранить regression seeds и итоговые stats релиза.

## 10. Метрики успеха 0.1.0

Предлагаемые продуктовые критерии для первых тестировщиков:

- Большинство игроков самостоятельно начинает матч менее чем за 2 минуты.
- Большинство понимает назначение кора, магазина и ресурсов после первого матча.
- Игроки используют строительство, а не играют только как в arena fighter.
- После первого матча понятна хотя бы одна сильная сторона выбранного героя.
- Критические crash/softlock отсутствуют.
- Есть желание сыграть повторный матч или попробовать другого героя.

## 13. Production pass — 2026-06-22

Реализовано:

- runtime-проигрывание валидных skeletal-анимаций героев с процедурным
  fallback для текущих статических GLB;
- внешние WAV/OGG SFX с процедурным fallback, категории Master/Music/SFX/
  Ambient, spatial attenuation/pan/pitch и защита от громкого дублирования;
- потоковая музыка для menu/match/intense/victory при наличии OGG-ассетов;
- направленное освещение, ambient, fog и пульсирующий emissive shader;
- resize-safe RenderTexture, render scale, bloom, vignette, color grade,
  damage flash и scope distortion с полным отключением post-processing;
- чанковые меши 16×16×16, hidden-face removal, отдельный прозрачный проход,
  dirty rebuild, distance/frustum culling, `UploadMesh`, `UpdateMeshBuffer` и
  `DrawMesh`;
- фиксированный пул частиц с уровнями качества;
- прокручиваемые scissor-настройки графики/аудио/accessibility;
- геймпад: стики, dead zone, чувствительность и переназначение кнопок;
- доступные не только по цвету формы команд на мини-карте;
- F8-метрики FPS/draw calls/chunks/triangles/rebuild time.

Проверка production pass:

- Release x64 собран без предупреждений проекта;
- Debug render-smoke подтвердил успешную компиляцию lighting/post shaders без
  warning/error/failure;
- `--startup-smoke` теперь запускает короткий реальный матч, создаёт и удаляет
  тестовый блок между кадрами и завершился с exit code 0 без зависших процессов;
- headless automatch: `--runs 1 --speed 32 --minutes 20 --seed 424242`, победа
  Blue, timeout=no, игровая длительность 805.531 с;
- GLB пересобраны с 16-bit indices, предупреждения raylib о конвертации u32
  устранены;
- кириллица в исходниках и документации проверена как UTF-8.
